The problem · stack AI 2026

Três forças tornam o stack AI hoje ingovernável

O vibe coder paga 5 subscriptions, instala 50 MCPs, escolhe entre 6 frameworks de agentes — e ainda assim não sabe qual usar para cada tarefa específica.

1

Modelos proliferam

Opus 4.7, GPT-5, Gemini 3.1, Llama 4, Qwen 3.5, DeepSeek-R1...

Cada modelo tem sweet-spot, custo, latência, contexto diferentes. Escolher errado custa 10-50× mais por turn.

2

MCP Registry explode

~10 000+ servers em PulseMCP / Smithery / Composio.

Anthropic registry oficial cobre ~20%. Sem ranking unificado, qual usar para X?

3

Skills sem registry oficial

Anthropic Skills: 17 oficiais · comunidade: ~66 000+

Discovery e qualidade são caóticas. Nenhum "ranker" emergiu ainda.

Resultado: tempo perdido a escolher, dinheiro queimado em modelo errado, e ferramentas certas que ficam por descobrir.

Anatomia · Moo Pack manifest

Um Pack é um manifesto declarativo · zero código

Ficheiro YAML em packs/<name>/pack.yaml. Descreve quando activar, o que invocar, e como compor o scaffold de sistema.

# packs/animation-web/pack.yaml name: animation-web version: 0.1.0 domain_signals: keywords: [animation, motion, scroll-trigger] intent_phrases: ["fazer animar", "transição suave"] file_extensions: [.tsx, .jsx, .css, .svg] model_floor: T2 skills: required: [anthropic-skills:web-artifacts-builder] mcps: recommended: [vercel, motion-canvas] subagents: primary: model-reasoner repos_canonical: - name: motion url: https://motion.dev license: MIT prompt_scaffold: | Default Motion (motion.dev) para React. 60fps non-negotiable. Respeita prefers-reduced-motion. adapter: # opcional (Wave 5) name: animation-web-lora-v1 base_model: qwen3:14b format: dora rank: 32

Composição declarativa

O Pack diz o quê, não como. O runtime resolve skills disponíveis, MCPs ligados, sugere instalação do que falta.

Trust score sindicado

Cada pack tem trust_score 0–1 calculado pelo hub (uso, validações, feedback). Discovery objectiva.

Adapter opcional

Wave 5: pack pode ter LoRA treinado em corpus público + traces sintéticas legais para o domínio.

Onboarding detecta GPU / VRAM / SUbscriptions e auto-decide quantização + modelo base que cabe. Routing T0 nunca pede o que não corre.

Recommendation engine

As 3 técnicas · não confundir

Quantização ≠ LoRA/DoRA ≠ Distillation

A força do Mooter está em combinar as três de forma consciente — cada uma com função distinta.

Quantização LoRA / DoRA Distillation
O que faz Reduz tamanho do modelo (peso em RAM/VRAM) Adiciona comportamento: estilo, padrões, naming Transfere raciocínio de prof → aluno
O que NÃO faz Não muda o que o modelo sabe Não cria inteligência geral nova Não fecha gap em capacidades emergentes
Custo treino 0 (post-processing) 3-6h RTX 4090 · ~5k examples Variável · depende do dataset
Footprint 4× menor (Q4 vs FP16) + 10-200 MB de adapter Modelo aluno completo
Quando usar Sempre (modelo local cabe no hardware) Quando há padrão repetitivo do projecto/domínio Quando o aluno tem capacity mas falta direcção
Risco legal Zero Zero (dados do user) Variável (ToS do modelo prof)
Combinadas: modelo local pequeno (qwen3:14b q4_K_M) + LoRA do projecto (5 MB) + processo de Sonnet (judge para eval) = competitivo com Sonnet em T1-T2 a custo $0 por chamada.

Moat · switching cost biológico

Cada user que usa 90 dias tem um Mooter diferente

Aderência cresce com uso · não com features

Wave 5+ — cada repo treina o Mooter um pouco mais. Adapter LoRA acumula no .mooter/ do projecto. Cada turn de feedback positivo é um data-point que afina os pesos.

Migrar para outro router significa começar de zero. Não é "habituação ao UI" — é perda real de capability acumulada.

Acumulação por camada

Camada 1 · user_priors.bin (2 KB)

LinUCB bandit. Velocity vs quality, lang preference, cost sensitivity. Maturity após ~2000 decisões.

Camada 2 · repo_fingerprint.bin (1.4 KB)

Vector 64-dim do estilo do repo. AST patterns, naming, async style, dominant frameworks.

Camada 3 · project.lora (10-200 MB) · Wave 5

Adapter treinado nos teus dados. Eleva qualidade local para próximo do cloud em tarefas T1-T2 específicas.

O moat não é a tecnologia. É o que a tecnologia acumula no teu dispositivo ao longo do tempo.
