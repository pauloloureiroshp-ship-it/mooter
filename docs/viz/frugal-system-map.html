Como o frugal melhora sozinho — o ciclo virtuoso
① USAR
Utilizador faz prompts no Claude Code
Cada prompt passa pelo inject_context.js. A decisão (tier, confidence, categoria, hardware) fica gravada em decisions.log na máquina do utilizador.
✓ funcional
② VER
Utilizador vê savings em tempo real
O savings-tracker.js serve o statusline: "⚡T0 | 87% saved | $4.20 poupado". Feedback imediato. Motivação para continuar a usar.
✓ funcional
③ APRENDER
backtest.js corre à noite
Detecta misroutes no corpus local. Gera/actualiza TUNED_DEMOTE_T3 para corrigir over-routing. Exporta eventos anonimizados. Sem LLM — pura regex + heurística.
✓ funcional (cron pendente no installer)
④ PARTILHAR
Eventos anonimizados vão para o hub
O hub-submit-events.js envia os eventos para o Cloudflare D1. Privacy contract enforced: sem texto de prompt, sem paths, sem PII. Só padrões de classificação.
✗ inject_context não chama ainda (MP-6)
⑤ AGREGAR
Hub processa dados da comunidade
Crons hourly/daily/weekly: agrega tier distributions, detecta anomalias, gera novo router-tuning a partir dos padrões de toda a comunidade. Mais utilizadores = modelo melhor.
⚠ crons activos, D1 vazio (depende de ④)
⑥ ACTUALIZAR
hub-pull.js distribui melhorias
No início de cada sessão, inject_context.js chama hub-pull.js que verifica se há novo router-tuning no hub. Se sim, actualiza o TUNED_DEMOTE_T3 local silenciosamente.
✓ funcional
O que falta para o flywheel girar a 100%
Passo ④ está incompleto: o inject_context.js não chama o hub-submit-events.js. Todos os outros passos estão prontos. Uma vez resolvido o MP-6 (hub connect), o flywheel completo fica activo.

O backtest corre via run-backtest.cmd em Windows, mas o LaunchAgent macOS para agendamento ainda não está no installer. Isso é o P3-C (não bloqueia beta).

O que falta para a versão sem vergonha — por prioridade
P0
Botão "Sign in with GitHub" na landing
A landing termina em ComparisonSection sem nenhum CTA de acesso. O utilizador não tem como entrar. OAuth App + Supabase provider já estão configurados (feito hoje). Falta só o botão.
→ MP-2: LANDING-LOGIN — Claude Code a executar agora
P0
Bug de sequência no onboarding + frugal_config não gravado
O Step 2 do onboarding faz OAuth redirect que limpa o state React (hw, subs). O utilizador perde as selecções. Além disso, saveProfile() não grava frugal_config nem email — os dados mais valiosos.
→ MP-3: ONBOARDING-FIX — Claude Code a executar agora
P0
Sem visibilidade dos utilizadores (sem /admin)
Não há forma de ver quem se registou, que hardware têm, se instalaram. Vais partilhar com friends sem saber quem são nem o que está a acontecer.
→ MP-4: ADMIN-PAGE — Claude Code a executar agora
P1
/api/install-complete não existe
Não há como saber se um utilizador que se registou efectivamente instalou o frugal. O funil fica cego: onboarding_completed ≠ install_completed.
→ MP-1 (do FRIENDS_BETA_ROADMAP.md) — criar endpoint + call nos installers
P1
Hub Cloudflare não recebe dados
O D1 está vazio. inject_context.js não chama hub-submit-events.js. O flywheel comunitário não gira. GET /api/stats devolve zeros. A landing mostra contadores live mas o hub está sem dados reais.
→ MP-6: HUB-CONNECT — após os P0 estarem resolvidos
P1
2 gaps de segurança na API
/api/me devolve accessToken ao browser (não devia — aumenta superfície de ataque). /api/profile não verifica se userId do query param corresponde ao user do token (qualquer user autenticado pode ler perfil alheio).
→ MP-5: SECURITY-FIX — Claude Code a executar agora
P2
email não é gravado no profiles
O email do utilizador (vem do GitHub OAuth) não é incluído no upsertProfile() do onboarding. A tabela profiles fica sem email → admin page mostra "—" para todos.
→ Incluído no MP-3: ONBOARDING-FIX
P2
FRIEND_KIT.md usa git clone (requer colaborador)
As instruções actuais para friends pedem git clone com SSH — o que requer que Paulo adicione cada pessoa como colaborador. Com o novo flow de login + onboarding, isto é desnecessário.
→ Actualizar para: "vai à landing → Sign in with GitHub → segue o onboarding"
P2
backtest.js não corre automaticamente (macOS)
O install.sh v2 instala um LaunchAgent mas não regista o backtest como scheduled task. Em Windows existe run-backtest.cmd mas não está no scheduler. O auto-learning só corre se o utilizador o fizer manualmente.
→ P3-C no roadmap — não bloqueia beta
