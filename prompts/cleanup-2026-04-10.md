### Step 3 — Reorganizar tools/router/

**IMPORTANTE**: Antes de criar as subpastas, mapeia todos os `require`/`path.join` em inject_context.js que referenciam outros ficheiros do router. Vais precisar de actualizar esses paths.

```bash
cd ~/frugal/tools/router

# Criar subpastas
mkdir -p core adapters analytics setup ui cli bench

# CORE — o que não pode falhar
cp classify.js core/
cp patterns.js core/
cp arbiter.js core/
cp pricing.js core/
cp inject_context.js core/
cp model-catalog.json core/

# Mantém os originais na raiz POR AGORA (não apaga ainda)
# Adiciona no início de cada ficheiro movido um require relativo correcto
```

**Atenção**: inject_context.js provavelmente faz `require('./classify')` ou usa `path.join(__dirname, ...)`.
Antes de mover, lê o ficheiro e mapeia todos os paths internos:

```bash
grep -n "require\|__dirname\|path.join" ~/frugal/tools/router/inject_context.js | head -30
grep -n "require\|__dirname\|path.join" ~/frugal/tools/router/classify.js | head -20
```

Só moves os ficheiros depois de teres mapeado todos os imports e saber exactamente o que vais mudar.

**Estratégia conservadora recomendada** (se os imports forem complexos):
Em vez de mover físicamente, cria symlinks ou usa um `index.js` que re-exporta.
A reorganização visual pode ser feita com subpastas que têm apenas `README.md` descrevendo
o que cada grupo de ficheiros faz, sem mover nada. Menos risco, mesmo benefício visual.

## O que NÃO fazer

- **Não mover** `tools/router/*.js` sem primeiro ler e mapear todos os `require()`.
  O hook de Claude Code chama `inject_context.js` por path absoluto — se mudares o path,
  o hook quebra e tens zero routing até fixar.
- **Não apagar** nada da pasta `agents/` — os subagents são referenciados por nome.
- **Não tocar** em `hub/`, `landing/`, `dashboard/` — são apps separadas com os seus próprios `package.json`.
- **Não mover** `SYNC.md`, `CLAUDE.md`, `ARCHITECTURE.md`, `ROADMAP.md` — ficam na raiz.
- **Não criar** ficheiros `.md` novos sem propósito claro.
