O Algoritmo — classify.js v0.10
Regex puro, 11 passes, zero LLM calls · JSON com tier, confidence, reasoning
Input → Output
// Input: string do prompt // Output: { "tier": "T2", // T0 | T1 | T2 | T3 "task_category": "debug_investigation", "recommended_backend": "claude_subagent", "recommended_model": "claude-sonnet-4-6", "suggested_subagent": "model-reasoner", "confidence": 0.8, "escalation_rule": "none", "reasoning": "med-risk signals: 2, high: 0", "variant_hint": null, // T0 sub-tier se aplicável "user_override": false, "previous_tier": "T2", // herdado da sessão anterior "anthropic_key_present": true, "prompt_length": 68 }
1
Cache Lookup
SHA256(prompt + prev_tier) → hit? retorna cached (30min TTL). Cache quente = 2ms.
2
MD Enrichment
Lê ## Router Context do CLAUDE.md do projecto. Contexto adicional sem custo.
3
User Override Detection
"usa opus" / "@sonnet" / "força haiku" → pin directo ao modelo pedido (excepto HIGH_RISK + downgrade).
4
Subagent Spawn Detection
"spawn model-architect" → user_override: true, tier preservado. Respeita intenção explícita.
5
Previous Tier Inheritance
Follow-ups curtos (<50ch) sem sinais herdam tier da sessão anterior via FRUGAL_PREV_TIER.
6
Fast Paths
BASH_PASTE (~30 CLI tools) → T0 terse. PS_PASTE → T0. READ_INTENT (lê/read + filename, curto) → T0 summarizer.
7
Score Principal (4 categorias)
HIGH(16 patterns) → T3. MED(14) + high==0 → T2. LOW(11) → T1. TRIVIAL(5) ou muito curto → T0. Else ambiguous.
8
Low-confidence Escalation
conf <0.5 AND (med>0 OR high>0) → bump tier +1. Só escala com evidência de risco.
9
TUNED_DEMOTE_T3
tier T2/T3 AND high==0 AND pattern match → force T1. Aprende do backtest diário.
10
TUNED_PROMOTE_T0
tier ≠ T0 AND high==0 AND pattern match → force T0. Aprende do backtest diário.
11
Degradações
T1 sem ANTHROPIC_API_KEY → T0. Budget >95% → hard cap T0. Falha-safe sempre para baixo.
⚠️ O Guardrail Dual-Enforce — a regra mais importante do codebase
O bug (2026-04-07): backtest aprendia "review final antes" como candidato a demote. Runtime bloqueava. Mas o router-tuning.json ficava envenenado e era re-injectado todos os dias.

A solução — duas camadas simultâneas:
Runtime (classify.js): if (high === 0) → só demote/promote se zero sinais HIGH_RISK
Upstream (backtest.js): if (hasHighRisk(d.prompt_preview)) continue → filtra corpus ANTES de derivar candidatos

A regra: quando o runtime bloqueia uma acção do pipeline de auto-learning, o pipeline que gera as regras também tem de ser ensinado a não propor essa acção.

Dados & Motor Proprietário
A arquitectura de dados é o activo central do frugal — não o código
Nível 1
🌐 Público (MIT)
classify.js, inject_context.js, install.sh, landing/, hub/ (worker público). O código que qualquer um pode ver e copiar. NÃO é o diferenciador.
Nível 2
👥 Comunidade (agregado, anónimo)
tier + confidence + prompt_len + hw_tier + cascade_path. Melhora o classify.js automaticamente. Parcialmente público (stats na landing). Via frugal-hub.
Nível 3
🔒 Perfil (privado por user, encriptado)
hardware, subscriptions, stack, GitHub repos metadata, routing history, savings history, custom patterns. Nunca sai da conta do utilizador. Base da personalização.
Nível 4
🔐 Motor (privado, repo frugal-core)
O modelo treinado nos dados do Nível 2. O dataset com labels de qualidade. As decisões de arquitectura do algoritmo. Nunca público. O segredo da Coca-Cola.
